# 半年报无法填充财务数据：修复与验收

日期：2026-09-20。

## 现场证据

用户上传的《铭普光磁：2026年半年度报告.pdf》已经完成 Markdown 转换（308,037 字符、4,552 行）。主要报表位于第 938–981 行，包含合并／母公司资产负债表、利润表和现金流量表，HTML 表格各自包含本期及对比期。

旧任务连续三次失败，错误码为 `task_execution_error`；数据库保存报表数为 0，因此不是前端隐藏了已识别的数据。旧实现将全文分块交给模型定位，再按单期提取，未利用转换结果已有的明确行列，且允许科目仅 52 项。旧错误没有保留异常类型，无法进一步证实具体外部调用或运行时异常，不能将其确定归因为超时。

## 修复

- 对有明确标题、主体、单位、列头的主要报表，直接读取源表单元格，优先于模型抽取。该路径无需 Agnes 凭据或网络调用。
- 六张源表按本期／对比期分别入库，保留主体、合并／母公司、期末／期初、半年累计范围。资产负债表期初对应上年末，利润和现金流量表对比期对应上年半年度。
- 标准科目映射继续使用既有契约；其他原始披露科目使用由本地原科目名称生成的稳定标识保存，模型响应仍受原标准科目白名单约束。这些新增披露行尚不接入自动公式计算。
- 每个值保留源表原行片段和 Markdown 范围，不从旁边单元格借值，不补零；每股收益单独使用元／股并保持四位小数显示，不随万元／亿元选择缩放。
- 任务保存源表数量、解析表数、数值覆盖数、空白数和不可读单元格数。覆盖不足标记 `passed_with_gaps`，不会宣称完整。
- 页面显示报表组数、数值数和源表覆盖信息，并可展开精确原文行片段。

## 适用边界

本地精确读取路径目前处理明确标题和简单列结构的 HTML 表格；复杂合并单元格或元信息不明会保留覆盖缺口或进入既有模型路径。此次 422/422 覆盖指转换后的六张主要报表单元格，不等同于证明 PDF OCR 无误或整份附注全部结构化。原表空白仍显示缺失，正式财务结论继续要求人工核对。
