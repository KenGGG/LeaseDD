# M0/M1 验收记录

本轮实施多人 WebUI 合成完整链路，不宣称完整 V1 或生产尽调报告已经交付。

## 实际能力

- React/TypeScript 中文工作台、项目概览、上传与文本证据、事实导入、指标、章节与任务进度、Word 下载及管理员配置。
- 独立账号、服务器 Cookie 会话、CSRF／同源检查；管理员不自动获得项目正文权限；项目成员校验覆盖原件、事实、任务、历史与报告下载。
- 原件摘要校验与不可覆盖存储；UTF-8 TXT/MD/CSV 原文行定位。首轮事实行要求明确科目和值，人工输入主体、范围、时点和元单位。
- 完整事实选择集追加历史，expected_revision 防止旧选择覆盖当前选择；重复候选不自动消除冲突。
- 三个 Decimal 比率，缺失存货、零分母、主体／范围／期间／单位冲突不产生有效数值；展示值由服务器确定。
- 数据库任务租约、单项目活动任务、最多三次尝试；错误 JSON、标题改动、未知引用、问题缺失和过期响应被拒绝。
- 章节保存使用版本校验并保留旧候选；导出按 lease token 隔离产物，旧 worker 不能覆盖有效报告。
- 固定合成 DOCX 模板副本生成，包含 w:tbl、指标与来源对照；全部角色禁用定稿发布。

## 测试范围

自动规则与 API 测试覆盖原设计用例中 F01–F05、F13、F18 的首轮适用部分，E07–E10 的适用部分，W02–W04、W09、W11 及 R01、R05–R07、R09、R13 的适用部分。这里只是行为关联，不代表这些场景在完整生产框架下已全部验收。

额外覆盖数值子串、科目与引用不匹配、事实／章节版本冲突、模型数据许可、Agnes 错误 JSON 的三次重试、过期任务与租约、独立导出目录、文件恢复完整性和真实 PostgreSQL 锁竞争。

真实浏览器验收：登录 → 创建成员／项目 → 编制账号上传 → 查看来源行 → 导入事实 → 计算 80.00%／30.00% 与存货缺口 → 后台测试章节 → 真实 DOCX 下载 → 审核账号只读。检查桌面 1440×1024 与移动宽度 390×844、无页面脚本错误、无移动横向溢出、原件与合成模板摘要不变。

生产 API 与 Web 镜像均完成干净依赖构建；隔离 Compose 栈使用 PostgreSQL 17，迁移到 0002，HTTPS 浏览器完整链路通过。测试浏览器仅为本地测试 CA 跳过证书信任检查，不代表团队设备证书安装已验收。

机器测试结果与运行命令写入 `test-results.json`。原始运行日志及浏览器截图、DOCX 位于 `runtime/`，均明确为合成测试。第三方 Starlette/AnyIO 的弃用警告单独记录，不作为业务通过证明。
