# LeaseDD 企业预警通财务数据优先导入设计

日期：2026-09-21

## 1. 目标与边界

LeaseDD 新建项目后，由后台按项目名称查询当前已登录的企业预警通浏览器会话，判断目标企业是否为上市公司且是否提供“财务数据”。企业预警通是财务数据源适配器，不是项目创建的前置依赖。

- 上市公司且有财务数据：以企业预警通为该项目的财务数据来源，后台复制“财务数据”栏目规定的全部内容及下级科目。
- 非上市公司或企业预警通明确没有财务数据：沿用 PDF → MinerU → Markdown → Agnes → 来源校验 → 财务恒等式流程。
- 企业匹配、登录或采集异常不得被解释为“非上市公司”或“没有财务数据”。
- 企业预警通导入失败或部分失败时不自动混入 PDF 提取值。
- 普通尽调材料仍可上传，但不得静默补齐或覆盖企业预警通财务数据。

本改造替代旧规格中“企业预警通仅作界面参考、不得作为生产财务数据来源”的边界。三张表的科目一致性、期间/单位校验和七条恒等式继续共用现有确定性逻辑。

## 2. 企业匹配与项目创建

管理员提交项目名称、编制人员和独立复核人员后，系统立即创建项目并分配成员，再异步提交企业匹配任务。企业预警通登录、网络或页面状态不得阻塞项目成立。

### 2.1 匹配结果

- 唯一明确匹配：自动绑定企业预警通规范名称和企业代码；有财务数据时继续提交后台导入任务。
- 多个候选：项目保持“等待选择企业”，管理员必须选择后才能绑定，系统不得默认选择第一条。
- 无结果或明确非上市公司：项目切换为普通资料识别流程。
- 上市公司但明确无财务数据：项目切换为普通资料识别流程，并记录判断依据。
- 登录失效、页面异常、超时或结构无法判断：项目保持“待匹配”，允许以后重试；不得自动解释为非上市公司或没有财务数据。

项目创建接口只承诺项目和成员创建成功，不等待企业搜索或财务采集。项目可以立即进入，财务栏目独立显示匹配与导入进度。

## 3. 浏览器会话边界

生产采集复用当前已经登录企业预警通的浏览器会话，访问用户正常可见的页面。

- 不读取、复制、持久化或返回密码与 Cookie。
- 不关闭或重启用户正在使用的浏览器。
- 浏览器连接参数属于服务端运行配置，不通过项目接口或网页泄露。
- 登录失效应产生明确的 `login_expired` 状态，由管理员恢复登录后重试。
- 页面结构变化应产生明确的结构不兼容错误，不得返回空数据并误报成功。

采集适配器与 LeaseDD 业务导入相互隔离：前者只负责企业搜索和取得原始结构化数据，后者负责版本、标准化、校验和展示。采集器必须保持薄适配器，不建设企业预警通镜像系统。

## 4. 数据范围

对于企业预警通中有财务数据的上市公司，目标范围是当前账号可访问的全部历史期间和下列栏目：

1. 主要财务指标。
2. 资产负债表。
3. 利润表。
4. 现金流量表。
5. 财务分析及其全部下级科目。
6. 财务附注及其全部下级科目。

“全部”包括页面展示的栏目层级、子模块、科目、期间、单位、原始值、空值、顺序及页面提供的主体/口径信息，但不得为了形式上的全覆盖把 LeaseDD 发展成网页爬虫维护项目。

采集优先级固定为：

1. 页面已有 JSON/XHR 等结构化接口。
2. 页面提供的 Excel/CSV 下载或导出结果。
3. 结构化 DOM 数据。
4. 仅在没有以上来源时使用局部 HTML/DOM 采集。

三张表和主要财务指标可以先完成、先展示，但最终交付和“导入完成”状态必须覆盖上述六类内容以及财务分析、财务附注的全部下级科目。任一栏目或下级科目未接入或失败时，批次必须标记“导入不完整”并列出缺口，不能以采集成本较高为由将其改成可选范围。

## 5. 版本化来源模型

新增以下逻辑实体；具体表名在实施计划中确定。

### 5.1 企业绑定

每个项目最多有一个当前企业预警通绑定，至少记录：

- 项目 ID。
- 企业预警通企业代码。
- 企业预警通规范名称。
- 上市状态和财务数据可用状态。
- 匹配方式、确认人和确认时间。

### 5.2 导入批次

每次创建后导入或管理员手动更新产生一个不可变批次，至少记录：

- 批次 ID、项目 ID、任务 ID。
- 开始和完成时间。
- `running`、`completed`、`partial` 或 `failed` 状态。
- 各栏目/子模块进度、失败原因、重试次数。
- 浏览器采集器版本、解析器版本及批次内容哈希。

批次同时记录“采集状态”和“质量状态”。三张表及主要财务指标成功后可以作为该批次的阶段性数据查看，但只有六类内容及其全部下级科目采集成功，批次才是 `completed` 并可替代上一完整版本。任何栏目或下级科目失败时，批次为 `partial`，保留成功内容和失败清单，但不替代上一完整版本。首次导入即部分失败时，成功内容可以查看，但页面必须持续标识“导入不完整”。公式异常只影响质量状态，不影响采集状态；在采集范围完整的前提下也不阻止当前版本切换。

### 5.3 最小来源证据

每个原始值至少保存：

- 页面 URL、企业代码、栏目路径、期间、单位、原始字段、原始值和采集时间。
- 所属原始响应或导出文件的内容哈希、采集状态和错误信息。

证据载荷的保存优先级为原始 JSON/XHR 响应、页面导出的 Excel/CSV、结构化 DOM 记录；只有无法用这些内容复核时才保存局部 HTML。系统不归档与财务值无关的完整网站页面。证据必须足以证明数字来自哪个栏目和期间，且不得包含认证秘密。旧批次不可原地覆盖或删除。管理员手动更新形成新批次，并可查看新旧差异。

## 6. 原始层与映射层

### 6.1 原始层

原始层完整保留企业预警通的栏目、层级、科目名称、期间表头、单位、原值、空值和顺序。任何标准化、公式检查或人工映射都不得改写原始层。

### 6.2 映射层

三张财务报表的原始科目可以映射到现有 LeaseDD 标准概念，以支持跨期展示、科目一致性检查和七条财务恒等式。

- 未知科目保留原名和原值。
- 歧义或错误映射不得作为公式输入。
- 映射结果需指回批次、来源快照、栏目路径、科目及期间。
- 主要财务指标、财务分析和财务附注优先按原栏目层级展示，不要求纳入三张表标准科目目录。

## 7. 确定性校验

企业预警通三张表复用现有校验原则：

- 仅在同主体、口径、期间、币种和单位下比较。
- 保留原始期间表头、币种和单位证据。
- 使用 `Decimal` 做单位换算和公式计算。
- 附注编号、序号等非金额列不能当作金额。
- 公式冲突不得清空、修改或反推原始值。

固定检查以下七条关系：

1. 资产总计 ≈ 负债合计＋所有者权益合计。
2. 流动资产合计＋非流动资产合计 ≈ 资产总计。
3. 流动负债合计＋非流动负债合计 ≈ 负债合计。
4. 利润总额－所得税费用 ≈ 净利润。
5. 营业利润＋营业外收入－营业外支出 ≈ 利润总额。
6. 经营净现金流＋投资净现金流＋筹资净现金流＋汇率影响 ≈ 现金净增加额。
7. 期初现金及现金等价物＋现金净增加额 ≈ 期末现金及现金等价物。

缺少披露项时显示“缺少披露项，未检查”，不得补零。舍入容差沿用各输入最后一位披露精度的半单位累加规则。

七条公式在企业预警通路径中只产生导入后的质量提示。公式冲突时数据照常导入，并分别记录公式状态、差额和涉及科目；公式未通过不得把采集成功批次改成失败。`采集成功` 与 `公式通过` 是两个独立状态。

企业预警通导入不调用 Agnes 做语义纠错；确定性解析或映射存在问题时标记待核对。PDF/Markdown 流程的 Agnes 定向复查仍只服务普通资料识别项目。

## 8. 来源隔离与更新

- 企业预警通绑定项目的财务主来源固定为 `enterprise_warning`。
- 普通资料识别项目的财务主来源为 `document_extraction`。
- 两种来源不得在同一当前财务版本中自动逐格合并。
- 企业预警通绑定项目可以上传、查看和下载普通尽调材料，但识别结果不得自动进入当前财务数据。
- 更新只由创建后的首次任务或管理员手动操作触发，不设置定时采集。
- 重试优先复用同一部分失败批次，跳过内容哈希未变化且已成功的栏目；完成后仍生成可审计的结果状态。
- 财务分析和附注采集期间，已成功的三张表及主要财务指标可以阶段性展示，但任务必须继续直到全部规定栏目成功或明确进入“导入不完整”。

## 9. 状态与界面

新建项目和财务页面至少表达：

- 待匹配或企业匹配中。
- 等待选择企业。
- 企业状态待确认。
- 企业预警通导入中。
- 导入完成。
- 导入不完整，可重试。
- 登录失效。
- 无企业预警通财务数据，使用资料识别。

项目创建后，多候选选择步骤在项目内展示，不阻塞项目建立。项目财务页显示数据来源、企业名称、企业代码、当前完整版本、六类栏目及下级科目覆盖、最近采集时间和失败栏目，并向管理员提供“从企业预警通更新”和“重试失败栏目”。

现有三张表视图和公式诊断继续使用。主要财务指标、财务分析和财务附注按原始层级折叠展示。本轮不建设复杂的人工纠错、审批或定时同步平台。

## 10. 权限、审计和并发

- 只有管理员可以在项目创建后确认企业候选、触发全量更新或重试采集。
- 项目成员沿用现有项目访问控制；非成员不得读取导入数据或来源快照。
- 创建、候选确认、企业绑定、导入开始/完成/失败、手动更新和重试均写入审计日志。
- 同一项目同一时刻只允许一个企业预警通导入任务运行。
- 重复提交应返回现有活动任务，不能并发重复采集。

## 11. 测试与验收

自动回归至少覆盖：

- 唯一匹配、多候选、无匹配、非上市公司、上市但无财务数据。
- 登录失效、页面异常、结构变化和部分栏目失败。
- 断点重试、重复提交、旧批次保留和完整批次切换。
- 六类规定栏目及全部下级科目的全部可访问期间、单位、空值和原值保真。
- 财务分析和财务附注的任一下级科目失败均进入缺口清单，并使批次保持 `partial`。
- 原始层不被映射或公式修改。
- PDF 数据不能静默进入企业预警通当前财务版本。
- 七条恒等式在企业预警通三表数据上复用，公式异常不改变采集成功状态。
- 项目成员权限、管理员操作和审计记录。

部署后创建或复用以下四个测试项目；同名项目存在时不得重复创建：

| 项目 | 编制人员 | 独立复核人员 |
| --- | --- | --- |
| 金银河 | tom | ken |
| 德方纳米 | tom | ken |
| 气派科技 | tom | ken |
| 昊志机电 | tom | ken |

逐项目记录企业匹配结果、企业代码、六类栏目及下级科目覆盖、期间数量、数字保真、三表公式状态、失败栏目、重试结果和采集耗时。现有“铭普光磁”项目不自动迁移。

## 12. 交付边界

交付包括：

- 不阻塞项目创建的企业搜索、绑定、后台采集、版本化导入和手动更新流程。
- 三张表和主要财务指标的快速阶段性可用、原始层展示及三表统一校验。
- 财务分析与财务附注全部下级科目的完整导入；缺少任一规定模块时不得宣称导入完成。
- 四个测试项目的实际采集结果和剩余问题清单。
- 浏览器会话失效与页面结构变化的明确诊断。

本轮成功标准是：新建四个上市公司项目后，不使用 Agnes，能够先较快提供三张表和主要财务指标，随后完整复制企业预警通“财务数据”栏目规定的六类内容及全部下级科目，并保证数字不变、期间不乱、来源可追。范围限于“财务数据”栏目，不复制企业预警通其他功能。四个样本通过仅证明这些样本及当前页面版本的表现，不宣称支持任意页面变化或长期无人维护的采集。
