# LeaseDD 企业预警通财务数据优先导入设计

日期：2026-09-21

## 1. 目标与边界

LeaseDD 新建项目时先按项目名称查询当前已登录的企业预警通浏览器会话，判断目标企业是否为上市公司且是否提供“财务数据”。

- 上市公司且有财务数据：以企业预警通为该项目的财务数据来源，后台导入完整财务数据栏目。
- 非上市公司或企业预警通明确没有财务数据：沿用 PDF → MinerU → Markdown → Agnes → 来源校验 → 财务恒等式流程。
- 企业匹配、登录或采集异常不得被解释为“非上市公司”或“没有财务数据”。
- 企业预警通导入失败或部分失败时不自动混入 PDF 提取值。
- 普通尽调材料仍可上传，但不得静默补齐或覆盖企业预警通财务数据。

本改造替代旧规格中“企业预警通仅作界面参考、不得作为生产财务数据来源”的边界。三张表的科目一致性、期间/单位校验和七条恒等式继续共用现有确定性逻辑。

## 2. 企业匹配与项目创建

管理员提交项目名称、编制人员和独立复核人员后，后端通过浏览器采集适配器查询企业预警通。

### 2.1 匹配结果

- 唯一明确匹配：绑定企业预警通规范名称和企业代码，并继续创建项目。
- 多个候选：返回候选企业的名称、企业代码及可辨识信息；管理员必须选择后才能继续，系统不得默认选择第一条。
- 无结果或明确非上市公司：创建普通资料识别项目。
- 上市公司但明确无财务数据：创建普通资料识别项目，并记录判断依据。
- 登录失效、页面异常、超时或结构无法判断：不得自动创建为普通项目；创建流程停在“企业状态待确认”，允许重试。

项目及成员写入成功后即向用户返回，不等待完整财务采集。若企业预警通财务数据可用，系统同时提交后台导入任务。项目可以立即进入，财务栏目显示导入进度。

## 3. 浏览器会话边界

生产采集复用当前已经登录企业预警通的浏览器会话，访问用户正常可见的页面。

- 不读取、复制、持久化或返回密码与 Cookie。
- 不关闭或重启用户正在使用的浏览器。
- 浏览器连接参数属于服务端运行配置，不通过项目接口或网页泄露。
- 登录失效应产生明确的 `login_expired` 状态，由管理员恢复登录后重试。
- 页面结构变化应产生明确的结构不兼容错误，不得返回空数据并误报成功。

采集适配器与 LeaseDD 业务导入相互隔离：前者只负责企业搜索和原始页面采集，后者负责版本、标准化、校验和展示。

## 4. 数据范围

对于企业预警通中有财务数据的上市公司，采集当前账号可访问的全部历史期间和下列完整栏目：

1. 主要财务指标。
2. 资产负债表。
3. 利润表。
4. 现金流量表。
5. 财务分析及其全部下级科目。
6. 财务附注及其全部下级科目。

“全部”包括页面展示的栏目层级、子模块、科目、期间、单位、原始值、空值、顺序及页面提供的主体/口径信息。采集器不能只抓隐藏 HTML `table`；应兼容页面中的表格、网格和动态加载模块。

## 5. 版本化来源模型

新增以下逻辑实体；具体表名在实施计划中确定。

### 5.1 企业绑定

每个项目最多有一个当前企业预警通绑定，至少记录：

- 项目 ID。
- 企业预警通企业代码。
- 企业预警通规范名称。
- 上市状态和财务数据可用状态。
- 匹配方式、确认人和确认时间。

### 5.2 导入批次

每次创建后导入或管理员手动更新产生一个不可变批次，至少记录：

- 批次 ID、项目 ID、任务 ID。
- 开始和完成时间。
- `running`、`completed`、`partial` 或 `failed` 状态。
- 各栏目/子模块进度、失败原因、重试次数。
- 浏览器采集器版本、解析器版本及批次内容哈希。

只有完整成功的批次可以自动成为项目的当前财务版本。部分失败批次保留成功内容和失败清单，但不替代上一完整版本。首次导入即部分失败时，成功内容可以查看，但页面必须持续标识“导入不完整”，且不能称为完整当前版本。

### 5.3 原始来源快照

每个栏目或子模块保存：

- 页面 URL、企业代码、栏目路径和采集时间。
- 原始结构化响应或可复现页面快照。
- 内容哈希、采集状态和错误信息。

来源快照必须足以复核导入值，但不得包含认证秘密。旧批次不可原地覆盖或删除。管理员手动更新形成新批次，并可查看新旧差异。

## 6. 原始层与映射层

### 6.1 原始层

原始层完整保留企业预警通的栏目、层级、科目名称、期间表头、单位、原值、空值和顺序。任何标准化、公式检查或人工映射都不得改写原始层。

### 6.2 映射层

三张财务报表的原始科目可以映射到现有 LeaseDD 标准概念，以支持跨期展示、科目一致性检查和七条财务恒等式。

- 未知科目保留原名和原值。
- 歧义或错误映射不得作为公式输入。
- 映射结果需指回批次、来源快照、栏目路径、科目及期间。
- 主要财务指标、财务分析和财务附注优先按原栏目层级展示，不要求纳入三张表标准科目目录。

## 7. 确定性校验

企业预警通三张表复用现有校验原则：

- 仅在同主体、口径、期间、币种和单位下比较。
- 保留原始期间表头、币种和单位证据。
- 使用 `Decimal` 做单位换算和公式计算。
- 附注编号、序号等非金额列不能当作金额。
- 公式冲突不得清空、修改或反推原始值。

固定检查以下七条关系：

1. 资产总计 ≈ 负债合计＋所有者权益合计。
2. 流动资产合计＋非流动资产合计 ≈ 资产总计。
3. 流动负债合计＋非流动负债合计 ≈ 负债合计。
4. 利润总额－所得税费用 ≈ 净利润。
5. 营业利润＋营业外收入－营业外支出 ≈ 利润总额。
6. 经营净现金流＋投资净现金流＋筹资净现金流＋汇率影响 ≈ 现金净增加额。
7. 期初现金及现金等价物＋现金净增加额 ≈ 期末现金及现金等价物。

缺少披露项时显示“缺少披露项，未检查”，不得补零。舍入容差沿用各输入最后一位披露精度的半单位累加规则。

企业预警通导入不调用 Agnes 做语义纠错；确定性解析或映射存在问题时标记待核对。PDF/Markdown 流程的 Agnes 定向复查仍只服务普通资料识别项目。

## 8. 来源隔离与更新

- 企业预警通绑定项目的财务主来源固定为 `enterprise_warning`。
- 普通资料识别项目的财务主来源为 `document_extraction`。
- 两种来源不得在同一当前财务版本中自动逐格合并。
- 企业预警通绑定项目可以上传、查看和下载普通尽调材料，但识别结果不得自动进入当前财务数据。
- 更新只由创建后的首次任务或管理员手动操作触发，不设置定时采集。
- 重试优先复用同一部分失败批次，跳过内容哈希未变化且已成功的栏目；完成后仍生成可审计的结果状态。

## 9. 状态与界面

新建项目和财务页面至少表达：

- 企业匹配中。
- 等待选择企业。
- 企业状态待确认。
- 企业预警通导入中。
- 导入完成。
- 导入不完整，可重试。
- 登录失效。
- 无企业预警通财务数据，使用资料识别。

新建项目表单在多候选时展示选择步骤。项目财务页显示数据来源、企业名称、企业代码、当前完整批次、最近采集时间和失败栏目，并向管理员提供“从企业预警通更新”和“重试失败栏目”。

现有三张表视图和公式诊断继续使用。主要财务指标、财务分析和财务附注按原始层级折叠展示。本轮不建设复杂的人工纠错、审批或定时同步平台。

## 10. 权限、审计和并发

- 只有管理员可以在创建项目时确认企业候选、触发全量更新或重试采集。
- 项目成员沿用现有项目访问控制；非成员不得读取导入数据或来源快照。
- 创建、候选确认、企业绑定、导入开始/完成/失败、手动更新和重试均写入审计日志。
- 同一项目同一时刻只允许一个企业预警通导入任务运行。
- 重复提交应返回现有活动任务，不能并发重复采集。

## 11. 测试与验收

自动回归至少覆盖：

- 唯一匹配、多候选、无匹配、非上市公司、上市但无财务数据。
- 登录失效、页面异常、结构变化和部分栏目失败。
- 断点重试、重复提交、旧批次保留和完整批次切换。
- 全部指定栏目及下级科目的层级、期间、单位、空值和原值保真。
- 原始层不被映射或公式修改。
- PDF 数据不能静默进入企业预警通当前财务版本。
- 七条恒等式在企业预警通三表数据上复用。
- 项目成员权限、管理员操作和审计记录。

部署后创建或复用以下四个测试项目；同名项目存在时不得重复创建：

| 项目 | 编制人员 | 独立复核人员 |
| --- | --- | --- |
| 金银河 | tom | ken |
| 德方纳米 | tom | ken |
| 气派科技 | tom | ken |
| 昊志机电 | tom | ken |

逐项目记录企业匹配结果、企业代码、栏目及子模块覆盖、期间数量、三表公式状态、失败栏目、重试结果和采集耗时。现有“铭普光磁”项目不自动迁移。

## 12. 交付边界

交付包括：

- 可运行的企业搜索、绑定、后台采集、版本化导入和手动更新流程。
- 企业预警通原始层级展示及三表统一校验。
- 四个测试项目的实际采集结果和剩余问题清单。
- 浏览器会话失效与页面结构变化的明确诊断。

四个样本通过仅证明这些样本及当前企业预警通页面版本的表现，不宣称支持任意页面变化或长期无人维护的采集。
