# 数据契约与命令接口设计

**性质：** 设计合同与合成示例；不是已实现 API，不是完整生成式 JSON Schema，也不是用户真实项目数据。生产 Schema 由实施阶段的 Pydantic 模型导出。

## 1. 统一约定

ID 在项目内稳定；对外/缓存引用使用 project_id + ID。所有产物带 schema_version、run_id 和 artifact hash。引用必须指向同项目、被当前运行快照允许的版本。

金额序列化为十进制字符串；币种采用明确代码；比例内部用小数，展示是否乘100由 display_format 决定。日期按 ISO 格式；报告截止时点与网页抓取时间不互相替代。

对于每个可能缺失的值，value 可为空，但 reason/status 必须解释空值。not_disclosed（来源未披露）与 missing（当前没有取得）不同；一律不能补零。事实被接受用于报告，不代表材料真实性自动认证。

事件、原始观察值和已发布产物追加版本；修改通过新事件/版本生效。禁止直接在多份 JSON 中分别修改同一个财务值。

## 2. SourceDocument 和 EvidenceSpan

下面为合成文字材料示例，刻意不伪造 PDF 页码/坐标。

```json
{
  "schema_version": "0.1",
  "project_id": "SYNTHETIC_PROJECT",
  "doc_id": "DOC001",
  "synthetic": true,
  "relative_path": "raw/synthetic_statement.txt",
  "sha256": "由入库程序对实际文件计算，不能由模型填写",
  "document_type": "financial_statement",
  "source_kind": "synthetic_fixture",
  "publication_date": null,
  "privacy_class": "synthetic",
  "parse_state": "pending"
}
```

```json
{
  "evidence_id": "EV001",
  "doc_id": "DOC001",
  "locator": {"kind": "text", "line_start": 2, "line_end": 2},
  "quoted_text": "资产总额：100元",
  "extraction_method": "plain_text",
  "verification": "locator_validation_pending"
}
```

实际 Schema 对 SHA256 使用64位十六进制约束；上述解释性字符串不能直接作为生产实例导入。Evidence 只有在程序校验文件摘要与定位内容后才可成为有效来源。

PDF locator 的字段：page_index、printed_page_label（可空）、bbox（可空）、bbox_coordinate_system（有bbox时必填）。DOCX locator 的字段：part、paragraph_index 或 table_index/row/column。XLSX locator 的字段：sheet、cell_range；补充 formula/cached_value 时不能混淆值的取得方式。

## 3. Fact 与候选选择

```json
{
  "schema_version": "0.1",
  "project_id": "SYNTHETIC_PROJECT",
  "fact_id": "F_ASSETS_001",
  "entity_id": "E001",
  "concept_id": "bs.total_assets",
  "scope": "consolidated",
  "period": {
    "kind": "instant",
    "start": null,
    "end": "2025-12-31",
    "basis": "fiscal_year_end"
  },
  "value": "100",
  "currency": "CNY",
  "base_unit": "yuan",
  "reported_value": "100",
  "reported_unit": "yuan",
  "source_evidence_ids": ["EV001"],
  "assertion_type": "reported_in_source",
  "selection_state": "candidate",
  "missing_reason": null,
  "revision": 1
}
```

流量事实的 period 必须同时给 start/end 与 cumulative/single_period 标识，不能只给期末日。

FactSelection 记录 logical_fact_key、candidate_fact_ids、selected_fact_ids、selection_reason、conflict_state、review_record_id。逻辑键相同出现不同值时，不能通过覆盖旧 JSON 消除冲突。

金额单位转换保留 multiplier 和输入 observation_id；转换来源是明确表头/单元格/人工确认，不是模型常识。外币换算另建派生事实，保留汇率来源和日期。

## 4. MetricResult

```json
{
  "metric_id": "M_LIABILITY_RATIO_001",
  "formula_id": "liabilities_to_assets",
  "formula_version": "v1",
  "entity_id": "E001",
  "scope": "consolidated",
  "period_end": "2025-12-31",
  "input_fact_ids": ["F_LIABILITIES_001", "F_ASSETS_001"],
  "value": "0.8",
  "status": "computed",
  "reason": null,
  "display_format": {"kind": "percent", "digits": 2},
  "risk_rating": null
}
```

缺失存货的速动比率应为：value=null、status=unavailable、reason=missing_required_input:bs.inventory。不能仍输出一个看似合理的数字并仅在日志警告。

公式文件只映射已登记的纯函数与参数，不使用 eval 执行模型提供的表达式。公式更改需要新版本及回归。Benchmark/风险阈值与指标分离，缺公司政策时保持 risk_rating=null。

## 5. SectionContract

下面 section_id 与 title 为合成技术示例，不冒充原框架真实章节编号。

```yaml
schema_version: '0.1'
section_id: SYNTH_SECTION_FINANCE
synthetic: true
title: 财务分析测试章节
ordinal: 1
framework_hash: 由框架编译器计算
questions:
  - id: Q001
    text: 当前总负债水平是多少，计算口径是什么？
    required_metrics: [liabilities_to_assets]
    evidence_policy: selected_financial_facts
  - id: Q002
    text: 有息负债与全部负债的关系是什么？
    required_metrics: [interest_bearing_debt_to_assets]
    evidence_policy: selected_financial_facts
  - id: Q003
    text: 当前资料是否足够计算速动比率？
    required_metrics: [quick_ratio]
    evidence_policy: data_availability
required_tables:
  - table_id: SYNTH_FINANCE_TABLE
    columns: [指标, 数值, 口径或缺口]
forbid_unbound_numbers: true
allow_gap_answer: true
allow_title_change: false
```

模板维护阶段将原框架的要求转成这种契约；不能在每次项目运行时重新由模型生成 questions 或 required_tables。

## 6. SectionDraft 与 Claim

```json
{
  "section_id": "SYNTH_SECTION_FINANCE",
  "task_id": "TASK001",
  "input_hash": "从task复制并由程序复核的摘要",
  "question_answers": [
    {"question_id": "Q001", "status": "answered", "block_ids": ["P001"]},
    {"question_id": "Q002", "status": "answered", "block_ids": ["P002"]},
    {"question_id": "Q003", "status": "gap", "block_ids": ["P003"]}
  ],
  "blocks": [
    {
      "block_id": "P001",
      "type": "paragraph",
      "segments": [
        {"type": "text", "text": "按总负债与总资产口径，资产负债率为"},
        {"type": "metric", "ref": "M_LIABILITY_RATIO_001"},
        {"type": "text", "text": "。"}
      ],
      "claim_type": "derived_from_metric",
      "support_refs": ["M_LIABILITY_RATIO_001"]
    },
    {
      "block_id": "P002",
      "type": "paragraph",
      "segments": [
        {"type": "text", "text": "有息负债率采用单独口径，为"},
        {"type": "metric", "ref": "M_INTEREST_DEBT_RATIO_001"},
        {"type": "text", "text": "，不代替全部负债率。"}
      ],
      "claim_type": "derived_from_metric",
      "support_refs": ["M_INTEREST_DEBT_RATIO_001"]
    },
    {
      "block_id": "P003",
      "type": "paragraph",
      "segments": [
        {"type": "text", "text": "现有资料未提供存货数，速动比率暂无法计算。"}
      ],
      "claim_type": "data_gap",
      "support_refs": ["GAP_INVENTORY_001"]
    }
  ],
  "table_bindings": [
    {"table_id": "SYNTH_FINANCE_TABLE", "dataset_ref": "T_FINANCE_001"}
  ]
}
```

允许的 segments 类型由 Schema 枚举，不接受模型传入任意 XML、HTML、Python 或模板表达式。table_bindings 指向程序建立的数据集，模型不能私改原始数值。

完整 Claim 增加 statement_type（reported / management_claim / calculation / inference / recommendation）、support_refs、counter_evidence_refs、assumptions、limitations。推断与建议不要求伪装成原件逐字陈述，但必须显示事实前提和不确定性。

## 7. 任务包与状态

Task 至少包括 task_id、project_id、run_id、kind、section_id、input_hash、dependency_hashes、allowed_evidence_ids、allowed_fact_ids、allowed_metric_ids、response_schema_path、output_path、attempt、max_attempts、privacy_policy_id。

模型不得修改 task input_hash 或 allowed_* 内容以自行扩大权限。import-result 对收到的 input_hash 与当前快照重算值比较；过期候选进入 stale，不覆盖当前章节。

三维状态示例：

```json
{
  "execution_state": "completed",
  "quality_state": "passed_with_gaps",
  "review_state": "pending",
  "export_eligibility": "review_only"
}
```

另一例：执行完但引用错误，应为 quality_state=failed，不能依靠 execution_state=completed 触发后续定稿。

## 8. 拟定命令合同

以下是拟开发命令，非上游现成命令。命令对stdout返回JSON或可读摘要；结构化JSON中必须有 execution_state、quality_state、review_state，不能靠exit code=0推断内容通过。

| 命令 | 读取 | 写入 | 前提 |
|---|---|---|---|
| doctor | 环境、依赖、策略 | 检查报告 | 不处理客户正文 |
| inventory | 授权raw目录 | 清单、文件摘要、初步缺口 | 项目路径与读权限明确 |
| parse | 清单、原件 | 页/段/表及Evidence候选 | 不执行原件代码 |
| import-facts | 人工/夹具候选 | 观察、事实候选、来源检查 | 来源必须存在且可定位 |
| reconcile | 事实候选、选择记录 | 冲突、标准化事实版本 | 不覆盖原观察 |
| calculate | 已可用事实、公式版本 | 指标、勾稽、缺口 | 检查实体/口径/单位/期间 |
| next-task | 当前状态、框架、Evidence | 锁定任务包 | 控制器选下一合法任务 |
| import-result | task、模型候选 | 校验结果、章节候选 | hash和Schema必须有效 |
| check | 全报告事实与章节 | 交叉检查、问题清单 | 只读事实，不自动补事实 |
| review-pack | 指标、章节、检查 | 人工复核包与差异 | 不生成假审核身份 |
| render --mode review | 固定模板、可用章节 | 待复核DOCX及manifest | 可显示明确缺口；不可泄露受限资料 |
| publish-reviewed | 人工确认记录、已验收DOCX | 定稿副本及manifest | 由Agent外的授权操作者执行，确认hash未变 |
| replay | 既有运行manifest | 重放/比对报告 | 默认复用已接受产物，不重新调用模型 |

缺口、失败、未支持能力、等候人工必须有稳定 reason_code。CLI进程退出码的映射由实现统一定义并测试；编排器读取完整状态，不仅读取进程是否退出正常。

## 9. 建议的阶段函数边界

```text
inventory(project_spec) -> InventoryArtifact
parse_document(source_document) -> ParsedDocumentArtifact
extract_candidate_facts(evidence_pack, task_response) -> ObservationBatch
select_facts(observations, decisions) -> FactsSnapshot
compute_metrics(facts_snapshot, formula_registry) -> MetricsArtifact
compile_section_plan(framework_lock, facts_snapshot) -> SectionPlan
build_section_task(section_contract, evidence_index) -> LockedTask
validate_section_response(locked_task, response) -> ValidationResult
build_report_model(accepted_sections, table_datasets) -> ReportModel
render_review_docx(report_model, frozen_template) -> ExportArtifact
```

计算函数和格式检查不依赖模型提供商、SQLite会话或UI对象。I/O、存储、模型任务与纯规则分层；业务代码不 import 上游四库。

## 10. 数据迁移与清理

Schema升级要保存输入旧版本和迁移记录；不能原地覆盖历史已发布run。缓存按摘要区分；清理缓存不影响原始资料与已确认报告。用户删除敏感项目时，需清理原件、解析文本、任务包、模型候选、索引和导出，而不是只删项目页面；云端宿主的数据保留另按实际产品权限与政策处理，不作本地程序可统一删除的承诺。
