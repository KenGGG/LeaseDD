# LeaseDD整合方案交付包

核查及成文日期：2026-09-18。

这是基于四个GitHub仓库关键源码核查形成的**实施设计包**，不是已经写好、安装或测试通过的LeaseDD程序。不包含四库源码、真实客户资料、字体或登录凭据。

建议阅读顺序：

1. `01_LeaseDD完整整合方案.md`：底座决策、完整架构、数据链、闸门、Word、隐私与里程碑。
2. `02_源码核查与迁移矩阵.md`：已读源码范围、发现和模块采用边界。
3. `05_数据契约与命令接口.md`：拟定接口和合成结构示例。
4. `04_验收场景与反例.md`：需要实现并执行的测试场景。
5. `03_Codex首轮实施指令.md`：只实施M0/M1的首轮任务，可连同完整方案交给本地Codex。

`upstream_audit.json` 保存已读文件的blob指纹和核查限制；它不是成功克隆/冻结四库commit的证明。正式实施时须另行核实本地commit与许可证。

方案选择：新建Python核心，DocForge做章节设计参考；Credit做计算架构参考；BidMaster/OpenBidKit只做阶段门禁和模板处理设计参考。不进行四库合并。

交付包尚未读取用户本机完整Word模板，因此没有虚构生产版章节manifest或最终可运行的JSON Schema。此项列入M0，缺失时可继续合成样例验证而不得假装生产完成。
