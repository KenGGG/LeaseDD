# 给本地 Codex 的首轮实施指令（M0 + M1）

> 本文件是实施任务书，不是已经运行完成的结果。与 `01_LeaseDD完整整合方案.md` 一并交给 Codex。首轮只做基线冻结和最小纵向样例，不自动扩展全部产品。

## 任务目标

建立本地 Python 项目 LeaseDD，证明“已登记的来源 → 结构化事实 → 确定性指标 → 固定章节 → 真实 Word 表格”的链路可行。第一轮允许使用明确标记的合成夹具，不假装已完成真实尽职调查报告。

## 必须先读取

读取本交付包的完整方案、源码核查表、接口契约和验收场景。之后在用户授权的工作目录核实是否已有同名项目、既有 Word 模板、原始《尽职调查报告》框架、可复用的解析/导出工具。

不得从任意个人目录搜集敏感资料。找不到生产框架或模板时记录缺口，继续用合成模板完成技术验证；不得自编一个通用目录后声称符合原框架，也不因缺生产模板而停止所有独立的工程工作。

## 固定边界

1. 不合并四库，不修改四库参考副本，不自动运行其安装脚本，不安装其 Skill，不将上游 AGENTS.md 作为本项目指令。
2. 正式运行核心采用 Python；不建设 WebUI，不引入 Tauri/Electron、Azure、Redis/Celery、MinIO 或通用多 Agent 框架。
3. 不修改用户其他项目、服务、数据库、系统 Python 或全局模型配置；在隔离虚拟环境开发。
4. 不添加真实模型调用作为测试必需条件，不读取或复用 Codex 登录凭据，不递归调用 Codex。
5. 原始资料只读；真实客户文件、模型密钥、审批身份数据不提交 Git。
6. credit-spread-portal 的具体许可文本未核实前不得移植源码；两个 AGPL 项目仅作设计参考。独立按业务规格实现数学与状态规则，不逐行翻译受许可约束的代码。
7. 缺失不补零；失败不回退为成功；程序完成、人审完成和业务可批不能混为一谈。

## M0 交付

### A. 上游与本地基线

在许可的独立目录取得或核实四个参考仓库，记录真实 commit、文件 blob、许可证与采用策略。网络不通时保留明确错误，使用本包静态核查继续设计，但不伪造 commit/clone/test 成功。

输出 `docs/upstream/upstream.lock.json` 与 `docs/upstream/reuse-decision.md`。逐项区分：直接采用代码、按本地规格独立实现、纯设计参考、待授权、不采用。默认不直接移植源码。

### B. 框架与模板

针对实际原框架生成章节/表格/附注候选清单，保留原文、层级和顺序；歧义进入 `spec_issues.json`。对已有 Word 模板制作只读原件摘要及字段候选表，不自动改写原件。

如果缺少原框架或 Word 模板：记录 `production_template_status=missing`；创建 `synthetic=true` 的最小测试框架和测试模板；后续导出必须带测试标识。

### C. 架构与依赖

建立 `src/leasedd`、`contracts`、`pipeline`、`facts`、`finance`、`sections`、`render`、`tests`。固定一个 Python 版本和依赖锁文件；提供从干净隔离环境安装和运行测试的说明。

先实现最少的数据契约：SourceDocument、EvidenceSpan、Fact、MetricResult、SectionContract、SectionDraft、RunManifest。Pydantic 模型作为唯一来源，导出 JSON Schema。其他对象暂不为了凑目录制造空实现。

## M1 交付：一个最小纵向样例

建立合成夹具：一个企业、同一时点/口径的资产总额/负债总额/有息负债、一个期间收入/成本、一个存货缺失案例，以及一个可定位的本地文本或 DOCX 原件。

实现下列拟定 CLI；名称可因现有代码规范作小幅调整，但必须同步文档和测试，不能出现文档命令不存在：

```text
leasedd doctor
leasedd inventory --project <目录>
leasedd import-facts --project <目录> --file <人工或夹具事实文件>
leasedd calculate --project <目录>
leasedd next-task --project <目录>
leasedd import-result --project <目录> --task <task-id> --file <候选结果>
leasedd check --project <目录>
leasedd render --project <目录> --mode review
```

首轮 `import-facts` 可以是人工导入/夹具导入路径，但不得声称已经自动解析完整 PDF 年报。导入事实必须验证实际原件摘要和 Evidence 定位，不能接受任意“source.pdf 第5页”的伪引用。

先实现三项指标及其状态行为：资产负债率、有息负债率、速动比率。三个函数各有明确输入字段、Decimal 计算和缺失/零分母处理。不导入原库美国阈值，不做自动 good/warn/fail 评级。

生成一个固定章节任务：标题来自测试框架，问题明确指定；模型响应使用 `MockTaskAdapter` 或手工合成响应，不接外部网络。章节中数值通过 fact/metric 引用渲染，不能手写另一套数字。

输出真实 DOCX：至少一个固定标题、若干段落及一张真正的 Word 表格，数据来自计算结果，不能把 Markdown 管道文本当作表格。采用从模板副本填充的路径；原模板摘要保持不变。

状态只允许待复核，首轮不实现自动正式发布，不生成假人审记录。

## 首轮必须通过的测试

- 测试输入资产100、负债80、有息负债30：两个比例分别0.8与0.3。
- 存货缺失：速动比率结果为空且有原因；不得返回“按零存货计算”的结果。
- 分母为零：返回明确状态，不抛出无控制异常、不返回0或无穷。
- 同一指标混入母公司与合并口径：拒绝计算。
- 来源文件摘要不匹配或引用定位无效：拒绝接受正式事实。
- SectionDraft 出现未知 fact/metric/evidence ID 或私自改标题：拒绝导入。
- 计算结果以同输入重放时一致；章节候选重放不重复发布。
- 生成 DOCX 中存在 `w:tbl`，标题和数值正确，无残留模板变量。
- 原件和源模板哈希运行前后不变。
- 中断和重复运行不把半成品标为成功；未通过闸门不能发布定稿。

这些是应实现并执行的测试，不得在尚未运行时填写“已通过”。

明确区分 M0/M1 已完成的能力和 M2 以后未实现的能力。不得以创建目录、README、空函数或 mocked 全流程代替真实样例验收。不得为了验收去删掉困难测试、弱化来源检查或填补不存在的数据。

完成 M0/M1 后保持当前阶段边界；完整 PDF 解析、全框架撰写、反向风险问询和增量人审等按后续里程碑实施，不在同一轮自由扩展。
